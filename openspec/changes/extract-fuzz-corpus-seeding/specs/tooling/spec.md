# tooling delta: extract-fuzz-corpus-seeding

Adds a fuzz-corpus seeding subcommand to the `tooling` capability, sibling to the
zero-copy, concurrency, and duplicate-code policies. Non-normative repository
tooling: it adds no AV2 conformance coverage. Tracked by
`INFRA-FUZZ-CORPUS-SEEDING`.

## ADDED Requirements

### Requirement: fuzz corpus seeding is a tested xtask subcommand

The curated `fuzz/corpus/<target>/` seed inputs SHALL be produced by
`cargo xtask seed-fuzz-corpus`, not by executable logic embedded in the CI
workflow. The subcommand SHALL read the committed `tests/fixtures/*.av2` corpus
and `tests/conformance/vectors/**/*.ivf` streams and write the seeds the
fuzz-smoke matrix relies on. Its byte-layout helpers (config prefixing, IVF
header/frame synthesis, IVF-to-OBU de-wrapping) SHALL be unit-tested in-process so
the logic is testable and locally reproducible. Tracked by
`INFRA-FUZZ-CORPUS-SEEDING`.

#### Scenario: seeding a fresh corpus

- **WHEN** `cargo xtask seed-fuzz-corpus` runs on a checkout
- **THEN** it enumerates the registered fuzz targets, copies each fixture into
  every target's corpus directory, and writes the config-prefixed, synthesized,
  and de-wrapped seeds for the validator, planner, decode-runtime, parse, and
  recon targets

#### Scenario: the produced seeds are byte-stable

- **WHEN** the subcommand writes a seed file
- **THEN** its bytes match the documented layout (the leading config prefix, the
  IVF header/frame fields, or the de-wrapped OBU payload), as asserted by the
  unit tests

### Requirement: CI invokes the subcommand instead of inline logic

The CI fuzz-smoke job SHALL seed each target's corpus by invoking
`cargo xtask seed-fuzz-corpus` as a single step, with no shell or Python seeding
logic embedded in the workflow. The corpus SHALL be regenerated by that command
in the job rather than shared across the matrix via a CI artifact. Tracked by
`INFRA-FUZZ-CORPUS-SEEDING`.

#### Scenario: the fuzz job seeds its corpus

- **WHEN** a fuzz-smoke matrix leg runs
- **THEN** it runs `cargo xtask seed-fuzz-corpus` to populate `fuzz/corpus/`
  before `cargo fuzz run`, and the workflow contains no inline corpus-seeding
  shell or Python
