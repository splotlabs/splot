## Context

`splot decode` currently stops at a structured unsupported diagnostic. The
decoder roadmap still needs a deterministic hash contract before future decoded
frames, fixture manifests, Y4M output, and encoder roundtrip checks can use
stable expectations.

This change is docs/OpenSpec only. It does not add `splot-recon`,
`splot-decode`, new public Rust types, runtime hash computation, fixtures,
dependencies, or external decoder integration.

## Goals / Non-Goals

**Goals:**

- Define the future repository-owned decoded-frame hash format in
  `docs/DECODER-ROADMAP.md`.
- Ground the contract in AV2 § 6.16.13 and § 7.21 output semantics.
- Mark the `deterministic-frame-hash` support row as `partial` with portable,
  self-contained proof commands.
- Keep AVM/dav2d evidence non-executable and optional.

**Non-Goals:**

- No dependency graph change.
- No `splot-recon` or `splot-decode` crate creation.
- No runtime decoder, frame buffer, or hash implementation.
- No emitted decode diagnostic change.
- No AVM/dav2d source, snippets, binaries, wrappers, scripts, tests, `xtask`
  commands, Cargo dependencies, build probes, or CI jobs.

## Decisions

1. Use AV2-aligned sample bytes with a versioned `splot` SHA-256 digest.

   AV2 § 6.16.13 already defines how decoded output samples are converted to
   bytes for metadata hash comparison: cropped output dimensions, raster order,
   Y/U/V plane order, one byte for 8-bit samples, and little-endian two-byte
   samples for bit depths greater than 8. Reusing that byte stream for future
   `splot` expectations avoids inventing a second pixel interpretation. The
   repo-owned fixture and roundtrip identity is `splot-dfh-sha256-v1`, not the
   AV2 metadata MD5 value. AV2 `hash_type = 0` MD5 remains a future interop
   check for `METADATA_TYPE_DECODED_FRAME_HASH`.

2. Hash visible cropped output samples, not backing allocation or stride.

   AV2 § 7.21.2 defines `OutY`, `OutU`, and `OutV` over the cropped output
   dimensions. Future `Plane<T>` storage may include stride or padding, but the
   hash contract must exclude those implementation details so encoder and
   decoder tests remain stable across storage layouts.

3. Default to raw decoded output before film grain.

   The first supported decode tier intentionally excludes film-grain
   application. The default future hash is therefore the `has_grain = 0` stream
   from AV2 § 6.16.13: `OutY`/`OutU`/`OutV` generated by § 7.21.2 before
   § 7.21.7 film-grain synthesis. A later film-grain-capable tier may add an
   explicit post-grain variant, but must label it separately.

4. Keep codec metadata outside the hash byte stream.

   Format metadata such as width, height, bit depth, subsampling, frame order,
   algorithm name, and variant belongs next to the hash in manifests or API
   fields. It is not included in the SHA-256 input. This keeps the sample-byte
   stream aligned with AV2 metadata decoded-frame-hash semantics and lets tests
   assert metadata separately.

5. Treat this as a contract-only partial feature.

   The support matrix row can become `partial` because docs and OpenSpec now
   define the future behavior, but it cannot become `supported` until source
   computes hashes from decoded output and self-contained tests prove it without
   external decoders.

## Risks / Trade-offs

- Spec ambiguity: AV2 § 6.16.13 supports both per-plane and whole-frame MD5
  metadata hashes. The first `splot` contract selects one whole-frame SHA-256
  digest over the same canonical sample bytes and reserves per-plane digests for
  explicit future support.
- Compatibility: AVM/dav2d may expose different local hash output formats. The
  committed contract records `splot` expectations and may cite local reference
  evidence only as non-executable metadata.
- Security: Future implementations must derive plane lengths with checked
  arithmetic and enforce `DecodeLimits` before hashing. This change documents
  policy only and adds no byte-consuming code.
- Maintenance: If the first supported decode tier later needs a different
  fixture hash envelope, the sample-byte contract should stay stable and the
  manifest wrapper should evolve around it.
