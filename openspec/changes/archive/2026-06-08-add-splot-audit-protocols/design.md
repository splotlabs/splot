## Context

The repository already has deterministic gates for formatting, clippy, tests,
license headers, crate dependency direction, AV2 spec mirror integrity, and feature
status drift. It also has a Claude PR review workflow with an AV2-aware prompt.
Those checks catch many regressions, but they do not provide a reusable audit
protocol for stale guidance or a stateful, changed-file AV2 conformance audit.

The attached knowledge-base audit protocol is a good model for documentation
freshness, but `splot` needs a second protocol for implementation/spec fidelity.
That second protocol must be able to coordinate multiple reviewers without letting
agent memory decide which files count as already audited.

## Goals / Non-Goals

**Goals:**

- Add two repo-local skills: one for documentation audit and one for AV2
  conformance audit.
- Keep `AGENTS.md` as a concise hub that points to the skills and avoids duplicating
  the protocols.
- Add deterministic audit-scope tooling that computes changed files from Git state
  and/or a content-hash ledger.
- Persist enough audit state to skip unchanged files on scheduled audits.
- Make audit output reviewable by humans and safe to run on demand.

**Non-Goals:**

- Do not add or change AV2 parser, validator, writer, encoder, or AVM behavior.
- Do not add new third-party dependencies.
- Do not auto-merge audit output.
- Do not hand-edit the AV2 spec mirror.
- Do not require every PR review to run the full heavy audit.

## Decisions

1. Use repo-local skills for protocols.

   The protocols are too large for `AGENTS.md` and too task-specific for generic
   instructions. Skills give progressive disclosure: always-visible metadata, loaded
   protocol only when requested, and optional bundled references/scripts later if
   needed. `AGENTS.md` should contain only a short pointer.

   The implementation should install project skills in the agent-specific paths
   this repository already uses: `.codex/skills/` for Codex and `.claude/skills/`
   for Claude Code. `.github/skills/` or `.github/prompts/` can mirror them only
   when a GitHub-hosted agent needs the same protocol. Do not rely on
   `.agents/skills/` as the sole repo location; it may be useful as a personal or
   tool-specific source, but it is not the repository's current cross-agent
   discovery path.

   Alternative considered: put both protocols directly in `AGENTS.md`. Rejected
   because it would make the canonical hub long and reduce the chance agents read
   the high-priority editing rules.

2. Use `xtask` or a checked-in script for audit scope selection.

   The heavy audit must not decide "changed since last audit" from an agent's
   memory. A deterministic command should emit the audit candidate set, impacted
   Feature IDs, and force-wide-review reasons. The initial implementation can be
   `cargo xtask audit-scope --format json`, or a script invoked by `xtask` if that
   keeps `xtask` small.

   Alternative considered: encode scope rules only in the skill prompt. Rejected
   because two agents could pick different file sets for the same tree.

3. Store an explicit audit ledger.

   The scheduled default-branch audit needs persistent state across fresh worktrees.
   Store a generated ledger under a project-owned path, tentatively
   `docs/audits/av2-conformance-ledger.json`, containing content hashes, last
   audited commit, impacted Feature IDs, audit protocol version, and outcome. The
   ledger should be generated by the audit-scope tooling and treated like other
   generated project metadata: reviewable, deterministic, and not hand-edited.

   Alternative considered: use scheduler-local state. Rejected because it is
   invisible to review and unavailable to other agents.

4. Force broader review on high-impact changes.

   Some files affect the meaning of many implementation files even when those files
   are unchanged. The audit-scope command should force affected-area expansion when
   any of these change:

   - `AGENTS.md`, `CLAUDE.md`, or `.github/copilot-instructions.md`
   - `.codex/skills/splot-*`
   - `docs/IMPLEMENTATION-MATRIX.toml`
   - `docs/SPEC-MAPPING.md`
   - `docs/FEATURE-TRACKING.md`
   - `docs/spec/av2/<version>/CHECKSUMS` or spec provenance pins
   - `xtask` audit-scope code

5. Discover audit scope from the moving repo shape.

   The heavy audit must not be limited to today's crate list. The scope command
   should discover workspace members from `Cargo.toml`, classify source files by
   owning crate/module, read Feature IDs from the matrix, and include in-scope
   files under future encoder, decoder, conformance, fuzz, script, workflow, and
   documentation paths. Today that includes `crates/splot-encode`; tomorrow it
   should automatically include any future decoder crate or encoder module as long
   as it is part of the workspace or matched by the repository's in-scope path
   rules.

   Alternative considered: hardcode `splot-core`, `splot-validate`,
   `splot-encode`, and `splot-cli`. Rejected because the audit would silently miss
   future codec-facing crates.

6. Keep multi-agent review coordinated, not authoritative.

   The heavy skill should define reviewer lanes such as spec citation, core parser,
   encoder/decoder behavior, validator diagnostics, feature matrix/OpenSpec,
   tests/fuzz/conformance, and safety/boundaries. The coordinator decides which
   lanes are relevant for the computed changed files, merges duplicate findings,
   and labels ambiguous spec interpretation as human-required. The workflow may
   spawn sub-agents only in environments where the user or scheduler explicitly
   authorizes parallel agent work.

7. Separate findings from fixes.

   Audit output may open a PR with protocol/ledger/doc fixes or produce a report,
   but AV2 implementation defects discovered by the heavy audit should generally
   become follow-up issues or dedicated OpenSpec changes. This keeps an audit from
   silently mixing review state with behavior changes.

## Risks / Trade-offs

- Ledger churn -> Keep the ledger deterministic and allow ledger-only PRs only for
  completed scheduled audits where persisting state is valuable.
- False sense of coverage -> Record the protocol version, candidate file set, and
  reviewer lanes used so a skipped file is skipped for an auditable reason.
- Missed transitive impact -> Force wider review for mapping, matrix, spec mirror,
  and audit tooling changes.
- Agent disagreement -> Require one coordinator report with deduplicated findings
  and explicit "human required" items for ambiguous spec interpretation.
- Over-broad audits -> Make the scope command the first step and allow explicit
  `--all` for deliberate full passes.
- Mixed-license mistakes -> Keep the AV2 spec mirror read-only and require audit
  protocols to cite mirror sections instead of copying spec text.
