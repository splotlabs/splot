PART 1. YOUR ROLE AND METHOD
==========================================================================================
You are the orchestrator for the x86_64 part of this work. Model: Fable. You decide what
to do, you write the briefs, you verify, you accept or reject, you commit. You do not write
the kernels yourself: delegate each implementation task to a cheaper subagent (Opus) in its
own git worktree. A second orchestrator does the same work on an Apple M2 (aarch64) at the
same time and pushes to `perf/faster-than-dav2d` (draft PR splotlabs/splot#1709).

Goal: `splot` (Rust AV2 decoder) must decode much faster than dav2d on x86_64 on every
stream, at 1 thread and at all cores. Each kernel must be faster than the dav2d kernel of
the same function (dav2d built with its x86 assembly). Thread scaling must be better than
dav2d's. The code must be lean: prefer deletion.

Read first: `AGENTS.md` (all of it; the section "Performance and SIMD" is the policy), then
this file. AV2 semantics come only from `docs/spec/av2/1.0.0/`.

Method that worked on aarch64 (use the same):
1. Measure before each decision. Primary metric: instructions retired at 1 thread
   (`perf stat -e instructions:u,cycles:u`). For the entropy parse use cycles (it is
   latency-bound). For thread scaling use wall time with alternating runs and medians
   (n >= 7) on a quiet machine. Report ranges. A delta smaller than the noise is not evidence.
2. Find the gap per stage and per kernel against dav2d: exclusive per-stage counters, a
   per-kernel class harness (instructions per call for each block size and filter class),
   and disassembly of both decoders.
3. One brief per subagent, one area per brief (files must not overlap between agents that
   run at the same time). Each brief gives: the goal as a number, the files, the baseline
   binary, the checks, the rules below, and the report format. Tell the agent to stop and
   report at about 80% of its context, with the exact next edits.
4. Do not trust a report. Before you commit agent work: apply its diff on the integration
   tree, build, run the hash check, the gate, the tests, and your own measurement.
5. Commit each accepted change as its own Conventional Commit, with a body that says what
   and why. Push after verification.
6. Keep a running log (see Part 5) so that the other orchestrator can read your state.

Rules for every agent (put them in each brief):
- Output must stay byte-exact. Frame hashes must equal the baseline:
  `splot decode --quiet --output-format hash -o - --threads=N FILE 2>&1 | grep -v thread_policy | md5sum`
  at threads 1, an odd count, and the core count, on all sample streams and on a 10-bit
  1080p stream. A hash difference means that the change is wrong.
- SIMD policy: one generic `fearless_simd` kernel (generic over u8/u16) when it is the
  fastest. If it is not, three versions: NEON, x86_64 (AVX2, `x86-64-v3` baseline), generic.
  No scalar sample-processing path at runtime (scalar code only in `#[cfg(test)]` as the
  oracle). Each SIMD version has a test against the portable kernel.
- Kernels can differ per architecture. Control flow, dispatch order, entry points and data
  layouts must NOT differ: `cfg(target_arch)` selects only a kernel module. A kernel that
  does not cover a shape declines to the shared portable path.
- An x86-only kernel module is deleted only after a measurement on x86 shows that the
  generic kernel is not slower. An aarch64 kernel is never changed without a check that
  aarch64 still compiles: `cargo clippy --workspace --all-targets --locked --target aarch64-unknown-linux-gnu -- -D warnings`
  (install the target with rustup). You cannot run aarch64 code: do not change NEON
  arithmetic. If shared code changes, the aarch64 orchestrator runs the hashes there.
- No new `unsafe` block without the maintainer's sign-off (ask the user). No new dependency.
  No `unwrap`/`expect`/`panic` in library code. No fixed caps on threads or frames.
- dav2d is inspiration only. Do not copy its code. Always improve on it.
- Gate before each commit: `cargo xtask ci --fast`, the tests of the touched crates in debug
  (`cargo test -p <crate> --locked`), clippy with `-D warnings`. Run the full `cargo xtask ci`
  before each push. Never pipe the gate through `tail`; read its exit code.
- The comment-density budget has no headroom: add no comments beyond a one-line "why".
  Add no Markdown files (the doc gate has an allow-list).
- Text style for briefs, commits and reports: ASD-STE100 Simplified Technical English.

PART 4. TASKS, IN ORDER
==========================================================================================
T1. Correctness of the branch on x86. `cargo xtask ci` (full). Hashes of the branch against
    `splot-main` on all streams at 1 thread, an odd count and the core count. Then a stress
    run for the new scheduler: at least 3,000 decodes of small streams at 2, 3, 4 threads
    and the core count, several processes at a time, each under a time limit; 0 failures
    and 0 timeouts are required. Stop and report to the user if anything fails.
T2. Baseline numbers. For each stream: branch against `splot-main` and against dav2d, at
    1 thread (instructions, cycles, wall) and at 4, 8 and all cores (wall, CPU time).
    Record geomean, total, and the ten worst streams at each thread count. On aarch64 the
    1-thread geomean against dav2d is about 2.5x to 3x and no stream loses.
T3. Per-stage and per-kernel gap table against dav2d x86 asm: entropy parse, mode info,
    inverse transform (8-bit, 10-bit), intra, MC by class (put / compound / cell, block
    size, H / V / HV, 8-bit and 10-bit), optical flow, warp, TIP, deblock, CDEF, CCSO, GDF,
    Wiener NS, PC-Wiener. This table selects the order of T4 to T6.
T4. Verify the x86 code that was edited without a run (marked AVX2-TOUCHED in Part 6).
    Highest risk first: the restored AVX2 MC kernels (`subpel_mc/eight_bit/avx2.rs`,
    `eight_bit/avx2/cell.rs`, `sixteen_bit/avx2.rs`), the AVX2 `search_window` signatures,
    warp `sheared_sum` and `column_dot_products`, GDF `InLane`, CDEF `InLane`/`MinPos`.
    Run `cargo test -p splot-recon --locked` and the hashes.
T5. Port each aarch64-only gain (marked ARM-ONLY in Part 6) to x86: write the AVX2 kernel
    behind the same kernel interface as the NEON kernel, or show by measurement that the
    generic `fearless_simd` kernel is at least as fast and use it. The largest ones:
    - MC: pair put kernel (`put_pair`), register cell kernels for 4x4 / 8x8 (rows unrolled
      at compile time, clamped windows), program kernel, stage-free strips, fused one-call
      compound, 10-bit register-ring two-pass, chunked fullpel. On aarch64 the 8-bit dot
      product (`sdot`/`usdot`) is selected per kernel class: measure `pmaddubsw` and, if
      the CPU has it, AVX-VNNI `vpdpbusd` per class in the same way.
    - 8-bit inverse transform: the structure of the NEON / generic kernel (no zero-skip
      masks below 32 wide, fixed trip counts, identity columns in the row pass, clamp
      folded into the add, DC-only and small paths) against the old AVX2 file.
    - Deblock: `portable_chunk` with the `still` early exit against the two AVX2 chunk kernels.
    - GDF: 8 lanes x 2 rows tap kernel against AVX2 `gdf_inlane.rs`.
    - Wiener NS and PC-Wiener by-lane kernels (one run flow, kernel choice differs per arch).
T6. For each module marked DELETE? in Part 6: measure the generic kernel against the AVX2
    module on 8-bit and 10-bit streams. Delete the AVX2 module where the generic kernel is
    not slower. Keep it, and say why, where it is faster.
T7. Control flow. Confirm with `grep -rn "target_arch" crates/` that each `cfg(target_arch)`
    selects only a kernel module or a kernel body. List each place where flow still differs
    and correct it (Part 6 has the known list).
T8. Scalar runtime paths that remain (scaled-reference MC `block::general` and `Sink::store`,
    `ext_warp_intermediate` border gather, `ext_warp_predict_scaled`, TIP per-cell gather,
    CDEF widening gathers): replace each with a generic `fearless_simd` kernel, if the
    aarch64 orchestrator has not done it when you reach this task (fetch first).
T9. Shared scalar code to re-measure on x86 (it was tuned on aarch64): the symbol decoder
    word path and CDF adapt (cycles), the mode-info parse (instructions per inter leaf
    against dav2d), the inter command build (a 320-byte memcpy), the inlining attributes of
    the generic post-deblock filter chain.
T10. Thread scaling on x86 (many cores, SMT). Measure per stream at each power-of-two
    thread count up to the core count against dav2d. Examine: the SeqCst fence on each
    dispatch (`mfence` or a locked instruction), the 128-byte padding, contention on the
    shared `ready` mutex and the `queued` counter at 32+ threads, wake placement on SMT
    siblings (`first_idle` wakes the lowest-index idle worker), the idle bitmask above 64
    threads (not tested), wake latency with futex park/unpark.
T11. Optional, only with a measured gain and the maintainer's agreement (ask the user):
    AVX-512 versions. The baseline stays `x86-64-v3`.
T12. Final report for the user: the T2 table again on the final head, the T3 table again,
    the list of deleted and kept x86 modules with numbers, what you did not check.
