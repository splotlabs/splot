# Test fixtures and the fixture manifest

`splot` keeps two distinct, committed binary corpora. Both are self-contained:
no external decoder, no AVM/dav2d, and no network are involved at test or CI time.

| Corpus | Location | Origin | Manifest | Used by |
| --- | --- | --- | --- | --- |
| Hand-crafted unit/CLI fixtures | `tests/fixtures/*.av2` | Hand-written `printf` byte recipes | `tests/fixtures/MANIFEST.toml` | the CLI/validator/inspector tests |
| Conformance vectors | `tests/conformance/vectors/**` | **Locally** generated by AVM, then committed | `tests/conformance/manifest.toml` | the conformance runner (see [CONFORMANCE.md](./CONFORMANCE.md)) |

This document covers the **`tests/fixtures/`** corpus and its manifest. The
conformance vectors are documented in [CONFORMANCE.md](./CONFORMANCE.md); byte-level
details and the `printf` regeneration recipes for each `.av2` fixture live in
[`tests/fixtures/README.md`](../tests/fixtures/README.md).

## Source-of-truth split

- `tests/fixtures/README.md` is the **byte reference** — hex, OBU decode, and the
  `printf` recipe per fixture (descriptive).
- `tests/fixtures/MANIFEST.toml` is the **machine-checkable, normative** record of
  each fixture's hash and expected validator outcome.
- `docs/FIXTURES.md` (this file) is the **workflow hub**.

## `MANIFEST.toml` schema

One `[[fixture]]` table per committed `.av2` file:

| Field | Meaning |
| --- | --- |
| `name` | Stable short id (unique across the manifest). |
| `path` | Path relative to `tests/fixtures/` (unique). |
| `sha256` | Lowercase hex SHA-256 of the committed bytes. |
| `description` | One-line human note. |
| `category` | `"valid"` \| `"validation-error"` \| `"parse-error"`. |
| `expect` | `"clean"` \| `{ diagnostics = ["rule-id", …] }` — the **error** rule-id set. |

`category` must be consistent with `expect` (enforced by `check-fixtures`):

- `valid` ⇔ `expect = "clean"`
- `parse-error` ⇔ `expect = { diagnostics = ["bitstream/parse-error"] }`
- `validation-error` ⇔ a non-empty `diagnostics` set other than the bare
  `bitstream/parse-error` set

The `expect` grammar matches `tests/conformance/manifest.toml` (`"clean"` or a
`{ diagnostics = [...] }` error-rule-id set compared for set equality), so the two
manifests can be reasoned about the same way.

## What guards the corpus

- **`cargo xtask check-fixtures`** (hermetic; no validator, no decoder, no network)
  verifies, for every `[[fixture]]`: the file exists, its bytes hash to the recorded
  `sha256`, `name`/`path` are unique, `category` is consistent with `expect`, and
  that **no** committed `tests/fixtures/*.av2` is missing from the manifest (no
  orphans). It is wired into `cargo xtask ci` and runs as a CI step. Tracked as
  `XTASK-CHECK-FIXTURES`.
- **`crates/splot-cli/tests/fixture_manifest.rs`** (under `cargo test`, hence under
  `cargo xtask ci`) closes the loop: it runs the real validator
  (`splot_validate::Validator::validate_bytes`, in-process — the same entry point as
  `splot validate`) over every fixture and asserts the recorded `expect`, so an
  outcome can never silently drift from the validator.

Together: `check-fixtures` pins integrity and metadata shape; the in-process test
pins that the metadata is *true*.

## Adding or changing a fixture

1. Create/regenerate the bytes with a `printf` recipe and record it in
   `tests/fixtures/README.md`.
2. Compute the hash: `shasum -a 256 tests/fixtures/<name>.av2`.
3. Add (or update) the `[[fixture]]` entry in `tests/fixtures/MANIFEST.toml` with
   the `name`, `path`, `sha256`, `description`, `category`, and `expect`. To learn
   the actual `expect`, run `splot validate --json tests/fixtures/<name>.av2` and
   take its **error** rule-ids (or `"clean"` if there are none).
4. Run `cargo xtask check-fixtures` and
   `cargo test -p splot-cli --test fixture_manifest`. A hash mismatch prints the
   on-disk hash so you can paste the correct value.

The root `.gitignore` ignores `*.av2` everywhere except `tests/fixtures/`, which is
explicitly un-ignored so the curated corpus is tracked.
