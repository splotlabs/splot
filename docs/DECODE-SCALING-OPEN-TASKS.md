# Decode Scaling Open Tasks

This is the live checklist for the work described in
[`DECODE-SCALING-MISSION.md`](DECODE-SCALING-MISSION.md). The mission records
measurements, rejected experiments, and architectural conclusions. This file
records what remains to be done.

## Update rule

When an investigation or implementation discovers another bottleneck,
correctness requirement, or prerequisite:

1. Add it here before continuing implementation.
2. Give it a stable ID, owner, status, dependencies, evidence, and next gate.
3. Keep only one implementation task active at a time. Read-only audits may run
   in parallel.
4. Do not delete rejected or completed work. Move its evidence to the mission
   ledger and update dependent tasks here.
5. A task is complete only when its stated correctness and measurement gates
   pass. Source code existing on a branch is not completion.

Statuses are `Open`, `Audit active`, `Investigation active`, `Fix active`,
`Implementation active`, `Blocked`, `Completed`, `Rejected`, and
`Rejected standalone`.

## Attachment reconciliation

The two architectural findings in the July 29 investigation remain required:

- Whole-frame synchronous entropy admission is `SCALE-011-A`. SCALE-003 rejected
  only the standalone POC, not multi-frame entropy admission in the cohesive
  row DAG.
- FIFO reconstruction backlog delaying publication is `SCALE-011-B`.
  SCALE-004 rejected only bounded scheduling around shadow surfaces, not
  dav2d-style row advancement around canonical ownership and real progress
  publication.

`SCALE-011-A` is now implemented and byte-exact inside the cohesive candidate,
but is not independently deliverable because it contributes only about 4%.
`SCALE-011-B` remains open after two exact standalone scheduler topologies
failed the architectural performance gate.
